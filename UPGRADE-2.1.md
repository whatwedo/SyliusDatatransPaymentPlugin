# UPGRADE FROM `v2.0.X` TO `v2.1.0`

* Requirements are now PHP `>=8.0` and Sylius `>=1.11` (Sylius 2.x is supported). `payum/core` and
  `symfony/http-client` are required explicitly.

* Datatrans status `transmitted` now completes the payment like `settled`, and `authorized` marks it as
  authorized instead of leaving it unknown. A paid or authorized status is only accepted if currency and amount match
  the Sylius payment.

* Currency and language are no longer hard-coded to `CHF` / `de`: the payment currency and the order locale are sent to
  Datatrans (language falls back to `de` if Datatrans does not support the locale).

* `/pay-from-link/{payment}` now requires a `token` query parameter with the order's token value, only works for
  payments in state `new` and returns a 404 otherwise. Links generated by `admin-link-payment.html.twig` include it;
  regenerate links you built yourself.

* The gateway `password` field is a password input now. The stored password is never rendered back; submitting it empty
  keeps the stored password. `sign` is optional.

* An existing transaction is only replaced if Datatrans reports a definite status for it that is neither paid nor
  authorized. If the status cannot be determined (error response, network error), no new transaction is created.
  `DatatransApi::hasPaidTransaction()` throws in that case.

* Replaced transaction ids are kept in the payment details under `previousTransactionIds` (they were overwritten
  before). Paid or authorized previous transactions are taken into account when checking the payment status.

* A paid transaction whose currency or amount does not match the Sylius payment is left for manual review: the payment
  is neither completed nor cancelled.

* `whatwedo:sylius-datatrans-payment:check-payment-status` only checks Datatrans payments in state `new` or `authorized`,
  continues with the next payment if one fails (discarding its changes; it stops with a non-zero exit code if the
  entity manager was closed) and uses the Sylius state machine abstraction when available. The two-week timeout only
  cancels payments in state `new` whose transaction Datatrans still reports as pending (`initialized`,
  `challenge_required`, `challenge_ongoing`, `authenticated`), counted from the later of the payment creation date and
  the transaction expiry. Error responses, `authorized` payments and paid transactions are never cancelled.
  `sign` / `hmac_sha256` are unused with JSON API v1 and may be left empty.

* Services are configured in `Resources/config/services.yaml` (the XML file was removed because Symfony 8 no longer
  supports XML service configuration). Service ids are unchanged.
